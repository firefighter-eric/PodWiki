### 1. 重要问题来自技术史与工业现场

- **嘉宾主张**：只跟随论文热点容易陷入学术内部循环；研究者应理解本领域历史，并以工程师心态进入工业现场。
- **依据与经历**：他认为自己直接写播放器产品代码的实习，比几次以论文为目标的研究院实习更能帮助后续研究，因为它暴露了真实约束、共性故障和产品边界。
- **边界**：这是个人研究路径总结，不能证明所有研究者都应进入企业，也不能证明工业现场发现的问题一定具有长期研究价值。

- **嘉宾主张**：ChatGPT 的特殊性在于它第一次让 AI 具有被所有人频繁使用的潜力，因此更像一次“互联网时刻”，而非普通应用热点。
- **依据与经历**：最初他也把它视为 hype；学生持续推动讨论后，团队注意到非专业用户也主动谈论和尝试它，进而转向大模型推理研究。

### 3. KV Cache 是“模型记忆”，也是新数据层的候选

- **嘉宾主张**：只要 Transformer 仍是主流架构，KV Cache 就是模型处理上下文后形成的内部记忆，并可能比人类可读文本更适合模型直接复用。
- **依据与经历**：他把 KV Cache 类比为“给模型看的视频”：人难以直接解释，但模型可以直接继续计算；其三维张量、体积和可存储、传输、复用属性也符合网络系统团队的能力。
- **边界**：类比用于帮助理解，并非严格技术等价；判断还依赖 Transformer 长期占主流、跨请求复用安全有效等前提。

### 4. LMCache 是研究缺少部署底座后的补位

- **嘉宾主张**：团队最初研究 KV Cache 压缩和非前缀复用，却发现工业界当时没有长期保存 KV Cache 的公共系统，因此不得不先补齐基础设施。
- **依据与经历**：他们先做研究，再向企业推广时发现请求结束后 KV Cache 通常即被丢弃，于是创建 LMCache；当前最容易被客户理解的价值是保存已有输入计算、降低重复 prefill。

## 5 分钟读完

江鋆晨的主线不是从一开始就选择 AI，而是持续选择自己愿意投入、又能突破限制的问题。他在姚班发现自己更关心系统能否继续提高，而不是只证明理论上限；后来又把产品工程经历视为研究能力的重要来源。[00:06:48] [00:47:52]

视频流媒体经历给了他一个重复使用的观察框架：当某类应用从少数公司扩展到普遍使用时，系统会需要新的数据分发、存储和分析层。流媒体时代是 HTTP 视频与 CDN，大数据时代是分布式数据系统；他据此推演 AI 也会产生自己的数据层。[00:29:10] [00:39:34]

团队在 2023 年决定转向大模型，并非因为当时 chatbot 已经足够强，而是因为它抓住了广泛用户的想象力。作为系统研究者，他们随后寻找体量足够大、可存储和传输的数据对象，最终选择 KV Cache。[01:09:32] [01:15:34]

研究过程先产生了压缩、复用等想法，之后才发现工业界缺少可承载它们的公共系统，于是 LMCache 从“让论文能够部署”的工具逐步变成开源项目和创业基础。短期商业价值是减少重复输入计算；长期押注则是管理模型自身形成的记忆。[01:17:53] [01:29:22]

最终愿景是让 KV Cache 成为跨推理引擎、硬件和存储的公共层，并服务更复杂的 agent 记忆管理。但这仍然是创业团队主动推动的技术判断，而非已经形成的行业共识；节目最值得保留的正是“判断—行动—风险”三者同时存在，而不是只复述成功故事。[01:37:49] [01:43:21] [01:53:31]
