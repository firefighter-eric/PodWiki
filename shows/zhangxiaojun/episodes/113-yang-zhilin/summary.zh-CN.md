## 一句话总结

杨植麟把大模型研发理解为一场没有固定终点的攀登：K2 一面用优化器、数据处理和更大稀疏度提高基础模型的 Token Efficiency，一面把 Agent 的泛化作为下一阶段核心难题，并期待最终用更强的“创新能力”让 AI 参与训练 AI。

## 为什么值得听

- 访谈把 K2 的技术选择拆成两条主线：基础模型如何在“数据墙”下提高学习效率，以及 Agentic 模型如何避免只在少数任务和基准上得高分。
- 杨植麟区分了强思考推理与多轮 Agent 两种 Test-time Scaling，也解释了为什么它们并非严格先后，却会共同决定模型能否参与研发下一代模型。
- 节目不只谈模型，还把产品、开源策略、组织管理和长期社会影响放进同一套“提出猜想—接受反馈—持续纠错”的框架里。

## 核心观点

| AGI 方向 | 每次进展都会打开新的问题空间 | 不用单一里程碑宣布“抵达” |

### 1. AGI 更像持续推进的方向，而不是可以宣布抵达的一阶台阶

- **嘉宾主张**：知识边界扩大时，旧问题被解决，新问题也会随之出现；所谓“无限的开端”不是没有进展，而是每次进展都会打开更大的问题空间。
- **依据与经历**：他以强化学习从“能训练”走到“如何评估复杂端到端任务”为例，说明技术答案会产生下一层验证与衡量问题。
- **边界**：这是杨植麟理解技术进步和 AGI 的哲学框架，不是可直接验证的工程里程碑定义。

### 2. 强思考与 Agent 是两种 Test-time Scaling，能力层级不必严格线性

- **嘉宾主张**：强思考模型在“缸中之脑”里反复提出和验证猜想；Agent 则通过多轮工具调用与外界交互。两者都在推理阶段扩大计算，但扩展的维度不同。
- **依据与经历**：他认为，Agent 可以在强推理还不充分时先解决部分任务；但若要完成最复杂任务，最终仍需把 Reasoning 和 Agentic 能力都做强。模型参与下一代模型研发，则是从 Agent 走向 Innovation 的关键标志。

### 5. 通用 Agent 的核心形式是多轮使用工具，Coding 只是重要子集

## 5 分钟读完

访谈从一座“没有尽头的雪山”开始。杨植麟借《The Beginning of Infinity》的问题观解释自己的研发心态：问题不可避免，但问题可以解决；解决一个问题不会终结探索，而会把知识边界推远，并暴露新的问题。由此，AGI 不是某天可以敲钟宣布完成的台阶，而是模型能力、社会应用与人类组织方式持续变化的方向。[00:03:39] [00:05:07] [00:07:20]

过去一年最明显的技术变化，在他看来是两种 Test-time Scaling。强思考推理让模型在内部多次提出猜想、验证和反思；Agent 则让模型通过搜索、浏览器、代码等工具与环境多轮交互。两者不必严格按先后发生：模型可能先表现出不错的 Agent 能力，再补强长链推理，但要完成最困难的开放任务，最终仍需同时提升两条轴。更远的一步，是让现有模型参与下一代模型的实验、分析和系统优化，从而进入 Innovation。[00:09:20] [00:12:14] [00:17:33] [00:19:28]

K1.5 对月之暗面更像强化学习路线的验证，K2 则同时押注更好的基础模型和更强的 Agentic 能力。基础模型侧的出发点是“数据墙”：高质量文本不会按算力同速增长，只让训练跑得更快，未必增加同等数据下的智能。团队因此关注 Token Efficiency，包括把 Muon 优化器扩展到大规模训练、改写高质量数据、增加稀疏模型参数。杨植麟称，这些选择让同一份数据产生更多学习收益；但节目中的倍数和稳定性结论仍需回到技术报告与实验设置核对。[00:24:47] [00:26:01] [00:27:11] [00:28:48]

Agent 侧最难的不是定义工具列表，而是泛化。一个模型可以在某项数学、编程或工具任务上通过强化学习显著涨分，却只在相邻分布上获得有限迁移。现有 Benchmark 又可能覆盖面窄、快速饱和，甚至诱导团队把模型优化成“只会考试”。杨植麟把下一步概括为“用 L4 解决 L3”：让 AI 参与环境、任务和对齐研究的生成，借更高层的创新能力改善 Agent 泛化。这仍是一项研究假设，而不是已经完成的方法。[00:31:57] [00:43:41] [00:44:11] [00:45:16]

他对 Agent 的最小描述是“多轮 + 工具”。多轮带来更长的任务时间和反馈链，工具让模型接入互联网、代码与业务系统。Coding 因为容易验证、能创造新工具，是通往数字世界自动化的重要子集，却不等于通用 Agent 的全部。真正通用的系统还要使用未见过的数据库、API 和领域工具，并在多步执行中保持稳定。[00:40:08] [00:41:07] [00:48:46] [00:49:30]

这种通用性也把模型架构和产品设计绑得更紧。长上下文不仅要长，还要在百万级信息中维持推理能力；多模态不仅要识图，还要复用文本模型已经学到的知识；Chat、Reasoning、Agent 与不同工具环境还不能互相干扰。所谓“模型级产品”，正是先把工具、上下文和交互环境纳入训练，再让模型在其中端到端学习。这样，产品核心并非模型外面的一层壳，而是训练方案的一部分。[00:51:42] [00:58:07] [01:01:35] [01:14:24]

开源策略也服务于这套路线。杨植麟认为，开源社区能优化推理、扩展部署，并让下游团队基于 K2 训练专用 Agent；但让基础模型本身继续进步，仍需要原厂的算力、数据和训练闭环。因此月之暗面希望持续分享模型和技术，却不会预先承诺一切都开源。通用一方产品与垂直 Agent 的边界，则要看谁掌握更独特的工具、评估和服务入口。[00:53:31] [00:54:12] [00:54:52] [01:16:37]
