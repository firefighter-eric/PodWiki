## 一句话总结

何俊贤把 DeepSeek 的技术演进拆成基座与推理两条线：从 LLM 的复现和 scaling law、细粒度 MoE、V2 的 MLA 到 V3 的工程扩展，再从 Coder、Math Shepherd、DeepSeek Math 和 Prover 走到 R1；他认为这不是突然出现的单点突破，而是以降低成本为约束、敢于偏离权威实践并持续验证的一系列积累。[00:17:32] [03:08:09]

### 3. DeepSeekMoE 用更多、更细的专家换取稀疏计算，并把小规模实验变成 V2 的前置验证

- **依据与经历**：首篇 MoE 工作主要在 2B/16B 等较小规模比较 64 个 routed experts 与传统少专家方案，并用约 2.8B 激活参数对照 7B dense 模型；未完成训练的 145B 试验则被解释为继续放大到 V2 的信号。[01:01:56] [01:03:38] [01:04:37]

### 4. V2 与 V3 把架构创新变成系统效率：MLA、专家扩展、MTP、FP8 和基础设施共同作用

- **嘉宾主张**：V2 的关键新增是 MLA——保留多头表达能力，却只缓存低维 latent representation，再还原 key/value，从而降低长上下文生成的 KV cache；V3 大体沿用 V2，再加入 loss-free balancing、multi-token prediction 和 FP8 训练。[01:06:50] [01:12:35] [01:46:49]

## 5 分钟读完

访谈先解释何俊贤为何很早关注 DeepSeek。他从幻方在大模型热潮前建设算力、向高校开放集群的经历谈起，认为团队后来公开模型、论文和技术细节的做法，延续了开放、严谨而低调的风格。这里最重要的不是替公司猜动机，而是确立读论文的线索：它是否愿意报告不利结果，是否真正验证了与主流不同的选择。[00:08:08] [00:12:40] [00:14:33]

第一篇 DeepSeek LLM 大体复现 Llama 2，却没有止步于“把数据做好”。论文研究 learning-rate schedule、超参数和 scaling law，试图用小规模实验预测大模型的最优配置和最终效果；评测部分还讨论多选题定向训练如何让榜单快速上涨。何俊贤把这种对 scaling law 与刷榜问题的公开分析，视作团队科学风格的早期证据。[00:21:02] [00:25:14] [00:41:48]

DeepSeekMoE 开始转向稀疏架构。模型把 feed-forward 部分拆成大量专家，每次只选择少数 routed experts，同时保留 shared experts 处理通用能力。总参数可以很大，激活参数和单次计算却相对小。首篇工作更多是验证性研究：小规模结果给了团队把专家数量进一步放大、最终做成 V2 的信心，也暴露出小模型结论能否迁移到大训练的风险。[00:47:21] [00:55:35] [01:05:32]

V2 把这条路线推到完整大模型，并引入 MLA。普通 attention 为避免重复计算，会保存历史 token 的 key/value；MLA 只缓存一个低维 latent，再映射回多头所需的 key/value，以更少显存维持多头表达。V3 延续 MoE 与 MLA，又叠加更多专家、multi-token prediction、FP8 训练和大量基础设施优化。节目把低训练成本和高吞吐解释为整套系统共同作用，而不是某个“魔法算法”。[01:12:35] [01:19:52] [01:45:30] [01:53:41]

推理线从 Coder 展开。代码模型先提供真实应用和 unit tests，Math Shepherd 再用过程监督判断数学推理步骤；DeepSeek Math 提出 GRPO，通过同一问题的多次采样和组内相对奖励拿掉 PPO 的 value model。更关键的是论文主动检查 RL 到底学到了新能力，还是只把基座已经会的正确答案排到前面，并较早展示 online 更新相对 offline 数据的优势。[02:05:41] [02:18:38] [02:29:18] [02:41:18]

奖励路线随后发生转向。Learned reward model 在分布变化时可能失准，规则奖励虽然稀疏，却更稳定；Prover 借助形式化 verifier，R1-Zero 则在数学和代码上直接检查答案与格式，从 V3 base 开始 RL。完整 R1 并非只有这一步：它加入 cold start SFT，对通用任务也仍使用 learned reward。因而，节目所说的“大道至简”是特定可验证分支的简化，不是训练数据、基座、后训练和工程全部消失。[02:43:38] [02:49:51] [02:54:18] [02:59:14]

最后的公司判断，是差异来自长期复利。DeepSeek 每一代都在成本约束下做一点不同：细粒度 MoE 降低激活计算，MLA 减少 KV cache，GRPO 降低 RL 资源，MTP 与 FP8 继续压缩训练和生成代价。何俊贤认为，正是这些不保证成功的小步尝试，让团队逐渐拥有自己的技术栈；至于未来是否继续靠预训练放大，还是转向合成数据、test-time scaling 和更大规模 RL，仍是开放问题。[03:08:09] [03:09:42] [03:12:29] [03:14:18]
