# Web 阅读器性能基准

本文记录 2026-08-07 的节目与单集导航加速，回答每一层改动分别减少了多少工作、带来了多少响应时间收益，以及哪些改动只改善反馈而不缩短网络时间。

## 结论

同一台机器、同一份 43 集内容、相同 Next.js 16.3.0 production 模式下，候选版本相对 `origin/main` 的 `59a16a4`：

| 页面 | 旧版 TTFB 中位数 / p95 | 新版 TTFB 中位数 / p95 | 中位数降低 | 约等于 |
| --- | ---: | ---: | ---: | ---: |
| 节目页 | 58.88 / 65.72 ms | 1.00 / 1.33 ms | 98.29% | 58.6× 更快 |
| 单集总结 | 58.37 / 69.63 ms | 1.03 / 1.29 ms | 98.23% | 56.6× 更快 |
| 单集逐字稿 | 61.80 / 71.91 ms | 2.32 / 2.74 ms | 96.24% | 26.6× 更快 |

旧版三个页面都是每次请求动态渲染，响应头为 `private, no-cache, no-store`。新版预生成 5 个节目页、43 个总结页和 43 个逐字稿页，响应头为 `s-maxage=31536000`；请求由静态产物响应，不再等待服务器读取 Markdown 和渲染 React。

## 各部分收益

### 1. 目录加载器：不再解析全库逐字稿

旧版的目录请求会调用同一个全量加载器。它读取 137 个选中 Markdown、7.734 MiB，并解析 56,990 条带时间码的原文或译文。新版将目录数据与正文数据分开：

| 加载场景 | Markdown 文件 | 读取量 | 带时间码段落 | 相对旧版节省 |
| --- | ---: | ---: | ---: | --- |
| 旧版全量加载 | 137 | 7.734 MiB | 56,990 | 基线 |
| 新版节目/单集目录 | 91 | 1.025 MiB | 0 | 文件 33.6%；字节 86.7%；段落解析 100% |
| 新版目标单集：Kimi K3 | 4 | 0.157 MiB | 932 | 文件 97.1%；字节 98.0%；段落解析 98.4% |
| 新版双语单集：李沐 | 5 | 0.078 MiB | 680 | 文件 96.4%；字节 99.0%；段落解析 98.8% |

目录仍读取节目 README、单集 README 和总结简介，因此文件数只减少 33.6%；真正昂贵的逐字稿读取与正则解析被完全移出目录路径。目标单集只读取自己的 README、总结、选中逐字稿和可选译稿，不再跨单集读取。

静态页面部署后，上述节目页和单集页在请求时的 Markdown 文件读取数进一步变为 **0**；加载器只在构建、开发模式和仍为动态的搜索接口中运行。

### 2. 节目页：动态渲染改为 SSG

节目页增加静态参数生成，5 个节目页随构建预生成。它的同机 TTFB 中位数从 58.88 ms 降至 1.00 ms，降低 98.29%；p95 从 65.72 ms 降至 1.33 ms，降低 97.98%。

### 3. 单集总结：移除请求期 `searchParams`

旧单集页读取 `searchParams` 来决定总结或逐字稿，Next.js 因此必须在请求期动态渲染。新版让基础路径固定为总结页，并预生成全部 43 个总结页。TTFB 中位数从 58.37 ms 降至 1.03 ms，降低 98.23%；p95 降低 98.14%。

### 4. 单集逐字稿：独立静态路径

逐字稿迁移到 `/shows/[showId]/episodes/[folder]/transcript`，同样预生成 43 个页面。TTFB 中位数从 61.80 ms 降至 2.32 ms，降低 96.24%；p95 降低 96.18%。

逐字稿页面比总结页大，因此静态响应仍需要约 2.3 ms，而不是 1 ms 左右。旧的 `?view=transcript` 保留 308 兼容跳转；站内链接已全部使用新路径，不承担这次跳转成本。

### 5. Loading 边界：改善感知，不计作网络加速

节目与单集路由新增可访问的 loading 状态。骨架延迟 120 ms 才淡入：快速静态导航不会闪屏，超过 120 ms 的网络等待会出现“正在载入”反馈。

这项改动不减少 TTFB，原始加速记为 **0%**；它解决的是慢网或缓存未命中时“点击后没有反馈”的感知问题。

### 6. 日期右移与动画整理：布局收益，不计作请求加速

节目名与日期右对齐，为多人名保留更多首列宽度。390 px 浏览器验证中，人物名与右侧元数据保持 14 px 间距，页面横向溢出为 0。

这项 CSS 调整不减少网络或服务器时间，原始加速同样记为 **0%**。

### 7. Vercel 函数追踪范围

旧配置把 `shows/**/*.md` 追踪到所有服务器函数。新版只让仍需全文内容的 `/api/search` 携带这些文件；当前构建的搜索函数追踪 182 个 Markdown，静态节目与单集页面不再需要对应的运行时函数包。

这主要降低部署函数的重复文件范围，不直接计入上面的页面 TTFB 百分比。

## 浏览器结果

候选版本本地 production 环境的真实浏览器测量：

| 操作 | 点击到目标内容完成两帧绘制 |
| --- | ---: |
| 节目页进入另一单集总结 | 20.4 ms |
| 总结切换到逐字稿 | 27.7 ms |

桌面与 390 × 844 移动端均无控制台错误或警告，移动端无横向溢出。这里记录的是候选版本绝对值；跨网络的生产环境数据在上线验收时另行测量，不与本地数据混算百分比。

## 代价与未优化部分

- 工作从请求期转移到了构建期：当前构建预生成 97 个页面，静态页面生成约 1.3–1.5 秒。
- 使用未压缩的 `Accept-Encoding: identity` 测量时，新版 HTML 体积比旧版增加：节目页 7.8%、总结页 11.1%、逐字稿 2.4%。本次收益来自消除请求期计算和启用缓存，并非缩小 HTML。
- `/api/search` 仍会读取并解析全部逐字稿。它不影响节目和单集点击，但这是内容规模继续增长后的下一项性能工作。
- 总结页在构建期仍读取目标逐字稿，以生成相关片段与章节；它不再发生在用户请求期。

## 测量方法

- 基线：`origin/main` 的 `59a16a4`。
- 候选：本次静态路由与内容加载拆分后的工作树。
- 两份源码分别独立执行 `npm run build` 与 `next start`。
- 同机回环地址、HTTP keep-alive、单连接、`Accept-Encoding: identity`。
- 每条路由预热 5 次，再交替请求旧版和新版各 40 次；p95 使用 nearest-rank。
- Node.js `v25.8.2`；页面内容在两份构建中相同。

启动旧版和新版 production 服务后，可用仓库脚本复现 HTTP 部分：

```bash
cd apps/web
OLD_BASE=http://127.0.0.1:3011 \
NEW_BASE=http://127.0.0.1:3012 \
PERF_WARMUPS=5 \
PERF_SAMPLES=40 \
node scripts/benchmark-routes.mjs
```

百分比使用 `(旧值 - 新值) / 旧值 × 100%`。本地 A/B 用于隔离代码变化；生产验收必须另看 Vercel 缓存响应头、真实网络、DOM、交互、响应式布局和浏览器控制台。
